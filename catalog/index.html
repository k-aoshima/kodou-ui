kodou-ui

どの道具でも使える基本の部品です。見た目は端末のまま、反応・説明・確認の出し方を今の質にしています。どれも触って試せて、押したキーと起きたこと、描画までの時間は下のステータスラインに出ます。

仕組み
  1. ライブラリは使いません。チェックの印、ツールチップ、エラーの枠、ログの絞り込みは CSS だけで出します（:checked :has() :hover）。
  2. 重ねて出すものは popover と <dialog> を使い、閉じ方とフォーカスはブラウザに任せます。
  3. イベントは部品ごとの親で1つだけ受けます。行ごとには付けません。
  4. 選択の移動は、変わった2行の印だけを書き換えます。表の並べ替えは行を作り直さず、並びだけを動かします。
  5. 1万行のリストは見えている行だけを描き、行の要素は使い回します。流れるログは上限つきで持ち、古い行から捨てます。
  6. 点の多いグラフは canvas に描き、描く幅の1列に1点まで間引きます。ドット絵のアイコンは、マスを行ごとにまとめた1本の path です。
  7. 画面外の節は content-visibility: auto で描かず、部品の中身には contain: content を付けます。
  8. 動きは transform と opacity だけです。描き直しは requestAnimationFrame で1回にまとめます。
  9. タイマーは1本にまとめ、頁が隠れている間と、部品が画面外にある間は止めます。

根拠references

昔の見た目のうち、読みやすさや使いやすさの研究から見て今の見せ方に替えた所の根拠です。詳しくは docs/research/retro-vs-modern.md にあります。

使った文献
  1. 文は字幅の変わる書体: Mansfield ほか 1996（Font Effects in Normal and Low Vision）、中野ほか 2010（UD 書体のリーダビリティ）
  2. 行の長さと行間、コントラスト: W3C WCAG 2.2 の 1.4.8、1.4.3、1.4.11、2.4.13
  3. 色だけで伝えない、CUD の色: W3C WCAG 2.2 の 1.4.1、岡部・伊藤（Color Universal Design）、Birch 2012
  4. 押せる範囲 24px: W3C WCAG 2.2 の 2.5.8
  5. ⌥ でキーを見せる: Grossman ほか 2007（Strategies for Accelerating On-line Learning of Hotkeys）、Giannisakis ほか 2017（IconHK）
  6. スピナーと進捗、応答時間: Nielsen 1993（Response Times）、Sherwin 2014（Progress Indicators）、Myers 1985
  7. 並びが変わる時だけ動かす: Heer・Robertson 2007、W3C WCAG 2.2 の 2.3.3
  8. エラーの書き方: Neusesser・Sunwall 2023（Error-Message Guidelines）、Command Line Interface Guidelines
  9. 確認より取り消し: Nielsen 2018（Confirmation Dialogs）、Raskin 2007、Anderson ほか 2015
  10. アイコンに文字: Harley 2014（Icon Usability）
  11. 棒グラフの読み取り: Heer・Bostock 2010（Cleveland・McGill の再現）
