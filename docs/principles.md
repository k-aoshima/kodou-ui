# 原則

Kodou-ui で作る画面は、次の4つで判断する。部品の選び方も、パターンの決め方も、ここから導く。

## 1. 手応え

入力1回ごとに、機械が目に見える形で応える。1文字打てば件数と並びが変わり、↓ を押せば選択が動く。

応えない入力は対話を切る。押したのに何も起きない、スピナーで待たされる、検索ボタンを押すまで結果が変わらない、といった画面は作らない。速さはそれ自体が目的ではなく、対話を途切れさせないための条件になる。目安は、キーを押してから描き変わるまで 50ms 以内、遅くても 100ms。重い処理は後ろに回し、出せる分を先に出す。

## 2. 中が見える

機械が何をどう解釈し、何をするのかを隠さない。

- 打った言葉がどの条件になったかを、その場で見せる（例：「先月のPDF」→ `#kind pdf` `#date 先月`）。
- 実行する前に、実際に動くコマンドや対象を見せる。
- 数字はぼかさず実際の値を出す。「処理中…」「最適化しました」のような中身の無い表示で済ませない。

## 3. ハンドルは人が握る

機械は提案し、決めるのは人。

- AI や補完の候補は、人が1キーで確定する。
- 自動の操作は、人が許可したときだけ動かす。
- 気を利かせた自動化で、人の操作を上書きしない。

AI の道具では、全部を任せる「自動運転」ではなく、人の操作に力を足す「パワーステアリング」を目指す。AI が今どのファイルを読み、何を変えようとしているかを常に見せ、人がいつでも割り込めるようにする。

## 4. うまくなるほど報われる

初めての人はマウスと一覧で使え、慣れた人は打つ量が減り、手が覚えて画面を見なくても操作できる。

- 同じ入力には、同じ結果を同じ順で返す。並びが毎回変わると手が覚えられない。
- 組み合わせられる小さな文法を用意する（接頭辞1つで絞り込みに入る、条件をつなげて書ける）。名前は既に知られた定番（シェル、Vim、Spotlight など）に合わせる。
- 何が打てるかを、空欄や接頭辞を打ったときに一覧で見せる。CLI の「覚えていないと使えない」を、今の UI で補う。

## 見た目

見た目は古く懐かしく、中身は今のものにする。等幅の文字の格子、罫線の枠、反転表示の選択、ステータスライン、`[  OK  ]` や `y/N` のような CLI の言い回しを残し、字体の描画、配色、動き、マウス操作、説明の出し方を今の質にする。

走査線、文字のにじみ、ちらつきのような CRT の劣化の再現は使わない。形は古く、描画はくっきりさせる。

## 文面の読みやすさ

形は古くしても、文として読むところの読みやすさは今の研究（認知科学、ユニバーサルデザイン）に合わせる。

- 文（説明、確認の問い、AI の発言、エラーの説明）は UD のプロポーショナル体（BIZ UDPゴシックなど）で組む。等幅は、コマンド、データ、表、格子のように桁をそろえるところだけに使う。
- 本文は 15px 以上、行間は 1.75〜1.85、1行は和文で 35〜40字までにする。
- 文字と地のコントラストは 4.5:1 以上にする。薄い色は飾り（かっこ、罫線）だけに使い、読ませる文には使わない。
- アイコンはドット絵（8×8 の格子を整数倍で描き、にじませない）にして、見た目の古さとそろえる。

## 速さと軽さ

手応えは速さで決まり、道具は一日中開いたままなのでメモリも食わせない。部品は次の作りを標準にする。

- ライブラリや依存を持たない。状態の見た目はできるだけ CSS で出す（`:hover` `:focus-visible` `:has`、`details`、`popover` 属性、`<dialog>`）。
- イベントは部品の親で1つだけ受ける。行ごとに listener を付けない。
- 一覧は全体を作り直さず、変わった行だけ差し替える。長い一覧は見えている行だけ描く。流れるデータは上限のあるリングバッファに入れる。
- 画面外は `content-visibility: auto`、部品の枠は `contain: content`。
- 動かすのは `transform` と `opacity` だけ。読み取りと書き込みは `requestAnimationFrame` でまとめる。
- グラフの点は描画幅のピクセル数まで間引く。点が多いものは canvas で描く。
- 頁が隠れている間と画面外では、タイマーとアニメーションを止める。
- 目標はキー入力から描画まで 16ms 以内（1フレーム）。入力から描画までの時間、要素数、メモリを画面に出して、道具自身の中も見えるようにする。

## 昔のままにするもの、今に替えるもの

根拠は [research/retro-vs-modern.md](research/retro-vs-modern.md)にある。

昔のまま残す（研究から見ても今の UI より良い、または同じ）:
- `[  OK  ]` `[FAILED]` のように状態を文字で書く。色に頼らない。
- 反転表示の選択。フォーカスと選択が見やすい。
- 詰めた一覧と、変わらない配置。慣れた人ほど速くなる。
- キー操作中心と、1キーごとの即座の描き変え。
- `[####----] 42%` や `3/50` の進捗。共通の基線から伸びるブロック文字の棒グラフ。

今に替える:
- 文は等幅をやめ、UD のプロポーショナル体にする。等幅は桁をそろえる所だけ。
- 状態を色だけで伝えない。記号か文字を必ず添える。
- 赤と緑は色相を CUD（カラーユニバーサルデザイン）寄りにし、明るさにも差をつける。
- 読ませる文は地に対して 4.5:1 以上。薄い色は飾りだけ。
- 明るい地を標準にし、暗い地は選べるようにする。
- エラーは何が起きたかと直し方を文で書き、コードや生ログは折りたたんで残す。
- 取り消せる操作は確認を出さずに undo にする。確認は取り返しのつかない操作だけ。`y/N` の既定は安全側にする。

折衷にする:
- 全部大文字は短い状態の語だけ。
- `[x]` のような小さい部品は、見た目は小さいまま、クリックできる範囲を 24px 以上にする。
- 動きは並びが変わる時だけ短く。reduced-motion では止める。
- スピナーは1秒未満なら出さない。10秒を超える処理は件数か割合を出す。
- ドット絵のアイコンには文字のラベルを常に添える。
- スパークラインは低くて比べにくいので、数字を横に添える。
- キーの学習は、ショートカットの表示を目立たせるだけでは進まない。修飾キーを押している間だけ、使えるキーを画面に重ねて見せる。
- 懐かしい見た目は好まれても、使いやすさを保証しない。見た目で選ばず、上の基準で確かめる。
