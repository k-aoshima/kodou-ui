# Kodou-ui で画面を作る

## 考え方

旧車の車体と手触りを残し、中身を今の技術に載せ替える改造を「レストモッド」と呼ぶ。Kodou-ui はツールの UI で同じことをする。

- **見た目は古いまま残す**: 等幅の文字の格子、罫線で囲んだ枠、反転表示の選択、ステータスライン、`[  OK  ]` や `y/N` のような CLI の言い回し、ANSI の並びの配色、ドット絵のアイコン。
- **中身は今のものにする**: 字体の描画、配色の見分けやすさとコントラスト、短い動き、マウス操作、解釈の説明、読みやすい文。CRT の走査線やにじみの再現はしない。

本質は**操作するよろこび**と**機械との対話**にある。速さそのものが目的ではなく、対話を途切れさせないための条件である。

レストモッドは考え方のたとえで、画面のアイコンや名前、文言に車の題材は出さない。

懐かしい見た目は好まれやすいが、それだけで使いやすくなる保証はない。見た目の好みで決めず、下の原則と `references/` の決まりで確かめる。

## 4つの原則

画面のどの部分も、次の4つで判断する。

1. **手応え**: 入力1回ごとに、機械が目に見える形で応える。押しても何も起きない入力、検索ボタンを押すまで変わらない結果、理由の分からない待ちを作らない。
2. **中が見える**: 機械が何をどう受け取り、何をするのかを隠さない。実行するコマンドと対象、数字の実際の値を見せる。「処理中…」「完了しました」だけで済ませない。
3. **ハンドルは人が握る**: 機械は提案し、決めるのは人。AI や補完の候補は人が1キーで確定し、自動の操作は人が許可したときだけ動かす。AI のツールは自動運転ではなくパワーステアリングにする。
4. **うまくなるほど報われる**: 初めての人はマウスと一覧で使え、慣れた人は打つ量が減る。同じ入力には同じ結果を同じ順で返し、手が覚えられるようにする。

## 作る順番

0. **プロジェクトの前提を読む**: プロジェクトの根に `DESIGN.md` があれば先に読み、「このプロジェクトの前提」（元にする手触り、主な流れ、アクセント）に従う。無ければ `assets/DESIGN.md` を根に写し、分かる所を埋め、分からない所は【　】のまま人に聞く。トークンの値を変えたら `DESIGN.md` と CSS の両方を直す。
1. **元にする手触りを決める**: fzf のように絞る、htop のように詰めて並べる、Vim のようにモードとステータスラインを持つ、のように、元になる CLI/TUI のツールを1〜2個に決める。
2. **キーボードで最後まで通る流れを作る**: 見た目は仮のまま、開く→打つ→選ぶ→実行→閉じるがキーだけでできるようにし、キーを押してから描き終わるまでの時間を測る（`performance.now()` と `requestAnimationFrame` で測って画面に出す）。目標は 16ms（1フレーム）以内。届くまで見た目に進まない。
3. **部品で組む**: 部品を一から書き直さず、用意した作りを写して使う。
   - 下の早見表から部品を選び、`references/components.md` でその部品の決まりを読む。
   - 作りは `assets/components/<名前>.html` にある（一覧は `assets/components/README.md`）。使う部品のファイルだけを開き、HTML と JS を写す。
   - 共通の CSS と関数（`tokens.css`・`kodou.css`・`virt.js`・`ledbar.js`・`kodou.js`・`icons.js`）は `assets/` からプロジェクトに写し、この順に読む。
   - アイコンは `references/icons.md` に従う。確認・エラー・待ち時間・文の書き方・速さの作り・React などの土台で使うときは `references/patterns.md` に従う。
4. **点検する**: `kodou-ui-review` スキルで点検し、指摘を直す。まず同じスキルの `scripts/check.py` を回す（コントラスト、アイコン、決まりの検出を 1 回で。`--measure` で軽さも測る）。比較のため、直す前と後の画面を撮って並べる。

## トークン

色・文字・余白・動きは CSS の変数で持ち、部品は変数だけを使う。値は `assets/tokens.css` にあり、見本帳 `catalog/index.html` の `:root` と同じもの。

| 種類 | 変数 | 使い方 |
|---|---|---|
| 地 | `--bg` `--panel` | 頁の地と、枠の中の地 |
| 文字 | `--fg` `--dim` `--faint` | 本文、補足、いちばん薄い文字。どれも地に対して 4.5:1 以上 |
| 飾り | `--deco` | かっこ、罫線、区切り。文字には使わない |
| 部品の境界 | `--ui` | 入力欄やボタンの枠。3:1 以上 |
| 選択 | `--sel-bg` `--sel-fg` | 反転表示 |
| 色 | `--red` `--green` `--yellow` `--blue` `--magenta` `--cyan` | ANSI の並び。色相は CUD 寄りで、赤と緑は明るさも変える |
| アクセント | `--accent` `--blue-hover` | フォーカス、主な操作、主な操作のホバー |
| 塗った面の文字 | `--on` | 色の面の上の文字 |
| 字体 | `--font` `--font-read` | 等幅（JetBrains Mono＋BIZ UDゴシック）と、文（OS の和文ゴシック） |
| 余白 | `--s1`〜`--s6` | 4・8・12・16・24・32px |
| 動き | `--t-fast` `--t-base` | 80ms と 140ms。動かすのは transform と opacity だけ |

明るい地を標準にし、暗い地は `prefers-color-scheme` と `data-theme="dark"` で切り替える。色を足したら `kodou-ui-review` の `scripts/contrast.py` で比を確かめる。

## 部品の早見表

| したいこと | 部品 |
|---|---|
| 操作を実行する | ボタン（時間がかかるものは件数つき） |
| 短い文字を入れる | テキスト入力（打つたびに確かめる） |
| 長い文を入れる | テキストエリア（行番号と行ごとの決まり） |
| 数を入れる | 数値ステッパー。量を感覚で決めるならスライダー |
| 決まった中から1つ選ぶ | 少なければラジオ、多ければセレクト、打って探すならコンボボックス |
| 入・切を決める | スイッチ（自動で何かする設定は既定を切）。複数選ぶならチェック |
| 複数の語を入れる | タグ入力 |
| 並べて選ぶ | リスト（件数が少なくても見えている分だけ描く） |
| 入れ子を見せる | ツリー |
| 設定や環境の値を見せる | キーと値 |
| 項目を比べる・並べ替える | 表 |
| 流れ続ける行を見せる | ログの流れ |
| 量を比べる | 棒グラフ。分布はヒストグラム |
| 時間の推移を見せる | 折れ線。点が多ければ canvas のグラフ。表の中ならスパークライン |
| 上限に対する今の量 | メーター |
| 待ち時間を見せる | 1秒未満は何も出さない。1秒を超えたらスピナー、10秒を超えたら進捗バー |
| 状態を短く示す | バッジと状態（文字か記号を必ず添える） |
| 起きたことを知らせる | 残るものは通知の帯、消えてよいものはトースト |
| 何も無いことを示す | 空の状態 |
| 画面を切り替える | タブ。階層の位置はパンくず、件数が多ければページ送り |
| 操作をまとめる | メニュー。キーを教えるのはツールチップ |
| 取り消せない操作を確かめる | その場の `y/N`。画面を止めるダイアログは最後の手段 |
| 部品を入れる | パネル（罫線の枠、左上に名前、下にキーの帯） |

## やりがちな失敗

| 失敗 | なぜ駄目か | 代わりに |
|---|---|---|
| 今どきのカード UI にして古さが消える | ただの新しい UI になり、Kodou-ui の意味がなくなる | 等幅の格子、罫線の枠、反転表示など TUI の形を残す |
| 走査線、にじみ、ちらつきで CRT を再現する | 読みにくくなるだけで、対話は何も増えない | 形は古く、描画はくっきり |
| 検索ボタン、「適用」ボタン | 打つたびに絞れる手応えを捨てている | 1文字ごとに結果を描き変える |
| 設定や確認をモーダルで出す | 操作の流れが止まり、確認は慣れて読まれなくなる | その場の1行、取り消し、ステータスライン |
| 打てるコマンドを README にだけ書く | 覚えている人しか使えない | コマンドパレットを空で開いたときに一覧を出す |
| 余白を大きく取ってカードを並べる | 一画面の件数が減り、目で探す時間が増える | 1行に情報を詰め、区切りは罫線と面で |
| 気を利かせて自動で実行・自動で直す | ハンドルを奪い、何が起きたか人が分からない | 提案して、人が1キーで確定する |
| 「処理中…」「完了しました」だけ出す | 中が見えない | 何を対象に何をしたかを、実際の値で出す |
| 同じ入力でも学習で並びが毎回変わる | 手が覚えられない | 並びは安定させ、変わるときは理由を見せる |

## 参考資料

- `assets/tokens.css`: トークン（明るい地と暗い地）
- `assets/virt.js`: 見えている分だけ描く仕組み（依存なし）
- `assets/ledbar.js`: 進捗バーとメーターの LED の帯（依存なし）
- `assets/kodou.css`: 部品の CSS（tokens.css の後に読む）
- `assets/kodou.js`: 共通の関数（frame・every・place・sl.msg・⌥ のキーの札）
- `assets/icons.js`: 110 個のドット絵のアイコンと `px()`
- `assets/components/`: 部品ごとの作り（37 ファイル）。開けばそのまま動く
- `assets/DESIGN.md`: トークンと決まりを DESIGN.md の形（google-labs-code/design.md）で書いたもの。プロジェクトの根に写して前提を書き足す
- `references/components.md`: 36 部品と土台（トークン、速さと軽さ、根拠）ごとの使いどころ、状態、決まり、使わない場面
- `references/icons.md`: マス目でアイコンを描く決まりと、今あるアイコンの一覧
- `references/patterns.md`: 確認と取り消し、待ち時間、エラー、文の書き方、色、キーの学習、速さと軽さ、React などの土台で使うとき
- 見本帳 `catalog/index.html`（Kodou-ui のリポジトリ）: すべての部品を 1 頁で触って試せる。`assets/` の CSS・JS・部品のファイルは、ここから `tools/build-assets.py` で書き出したもの
- 原則 `docs/principles.md`、根拠 `docs/research/retro-vs-modern.md`

`assets/` と `references/` はこのスキルのフォルダの中にあり、スキルだけを入れても使える。部品の作りもアイコンも `assets/` に入っているので、見本帳が無くても同じ物を作れる。`catalog/`・`docs/`・`bench/` は Kodou-ui のリポジトリにあり、人が見て確かめるためのもの。点検のスクリプトは `kodou-ui-review` スキルの `scripts/` にあるので、2 つのスキルは一緒に入れる。
