# Kodou-ui の画面を点検する

作る側の決まりは `kodou-ui-build` スキル（SKILL.md と references）にある。点検はその決まりに照らして行う。スクリプトはこのスキルのフォルダの `scripts/` にある。`check.py`・`lint.py`・`contrast.py`・`icon.py` は Python 3 の標準ライブラリだけで動き、`measure.mjs` は Node と puppeteer-core と Chrome を使う。下のコマンドの `scripts/` は、このスキルのフォルダからの相対。

## 手順

1. **スクリプトで測れるものを先に測る**: まず `check.py` で全部をまとめて回す。終了コードは 0 が全部通った、1 が基準を割るものがあった、2 が回せなかった。CI にもそのまま載せられる。
   ```sh
   python3 scripts/check.py path/to/page.html src/      # 下の 3 つをまとめて回し、結果を表で出す
   python3 scripts/check.py path/to/page.html --measure # 加えて軽さも測る
   ```
   1 つずつ回すときは次のとおり。
   ```sh
   python3 scripts/lint.py path/to/page.html src/       # 決まりの検出（規則は --rules で一覧）
   python3 scripts/contrast.py path/to/page.html        # 文字と地のコントラスト比
   python3 scripts/icon.py path/to/page.html            # アイコンのマス目（PX12）
   python3 scripts/icon.py path/to/page.html --set PX   # 8×8 のアイコン
   node scripts/measure.mjs path/to/page.html           # 要素の数、JS のヒープ、見えている間と隠れている間の忙しさ
   ```
   `contrast.py` は素の `:root` と `:root[data-theme="dark"]` のトークンを読み、文字（4.5:1）、部品の境界とフォーカス（3:1）、塗った面の上の文字を表で出す。基準を割るものがあると終了コード 1 を返す。トークンの名前が違う画面では `--text` と `--ground` で指定する。`lint.py` は、ファイルを読むだけで分かる決まりの違反を探す。たとえば confirm()・「処理中…」だけの表示・「検索」ボタン・左端の色の縦線・消したフォーカス・止めない動き・隠れても回るタイマーで、見つけたものは下の「指摘の出し方」と同じ形で出す。わざと残す所は、同じ行か 1 行前に `kodou-lint: ignore 規則名` と書く。lint で見つからなくても、チェックリストは省かない（規則で見つけられるのは一部だけ）。
2. **ブラウザで操作して見る**: キーボードだけで、開く→打つ→選ぶ→実行→閉じるが通るかを試す。マウスでも同じことをする。ライトとダーク、狭い幅（400px）でも見る。
3. **チェックリストを1つずつ当てる**（下）。
4. **速さを測る**: `measure.mjs` の結果（要素 3,000 以下、隠れている間の忙しさ 1% 以下が目安）と、画面に出しているキー入力から描画までの時間を読む。キー入力から描画までの時間を出していなければ、出すこと自体を指摘する。
5. **指摘を出す**（下の形）。直したら、直す前と後の画面を撮って並べる。

## チェックリスト

### 4つの原則
- [ ] 手応え: どの入力にも目に見える応答がある。押して何も起きない所、ボタンを押すまで結果が変わらない検索がない。
- [ ] 中が見える: 入力を機械がどう受け取ったか（何件中何件か）、実行するコマンドと対象、実際の数値が見える。「処理中…」「完了しました」だけの表示がない。
- [ ] ハンドルは人: 自動で動く操作は既定が切で、AI や補完は提案までで人が確定する。気を利かせた自動実行がない。
- [ ] うまくなる: キーボードで最後まで通る。同じ入力で並びが変わらない。キーがメニューやツールチップに書いてあり、⌥ で重ねて見せられる。

### 見え方
- [ ] 読ませる文字は地に対して 4.5:1 以上、部品の境界とフォーカスは 3:1 以上（`contrast.py`）。
- [ ] 状態、系列、境目の超過を色だけで伝えていない（文字・記号・形が添えてある）。
- [ ] フォーカスはアクセント色 2px の実線で、どの部品でも見える。点線ではない。
- [ ] 選択は反転表示で、左端の色の縦線を使っていない。
- [ ] 枠のあるボタンに角かっこが付いていない。ホバーはボタン自身の色を濃くしている（黒で反転していない）。
- [ ] 文はプロポーショナル体で、等幅はデータとコマンドだけ。本文 15px 以上、行間 1.75 以上、1行 40字まで。
- [ ] アイコンに文字ラベルがある（無いものはツールチップと `aria-label` がある）。アイコンは同じ格子に乗っている（`icon.py`）。

### 操作
- [ ] 押せる範囲が 24px 以上（チップの ×、小さいボタン、チェック、ページ送り、コピー）。
- [ ] 1秒未満の処理にスピナーが出ない。1〜10秒はスピナーに内容と件数か時間、10秒超は進捗バー。
- [ ] 進捗バーとメーターは LED の帯（4px のブロックを 2px あけて並べる）で、割合だけにせず数字と件数・時間・今の対象を添えている。内訳は斜線、上限は赤い線、境目の超過は文字でも出している。
- [ ] 取り消せる操作に確認を出していない（取り消しのトーストがある）。取り返しのつかない操作だけ確認し、既定は安全側。
- [ ] エラーは何が起きたかと直し方を文で書き、コードや生ログは折りたたんで残している。
- [ ] 動きは並びが変わる時だけで、`prefers-reduced-motion` で止まる。

### 速さと軽さ
- [ ] キー入力から描画まで 16ms 以内（測った値を書く。測れなければ測れないと書く）。
- [ ] 数が決まっていない集まり（リスト、ツリー、表、候補、ログ、会話）は、件数が少なくても見えている分だけ描いている。流れるデータは上限つき。要素の数を書く。
- [ ] 見えている分だけ描く一覧では、フォーカスが箱にあり、選んでいる行を `aria-activedescendant` で示している（行の要素にフォーカスを置いていない）。
- [ ] 一覧の更新で全体を作り直していない。イベントは委譲。
- [ ] 頁が隠れている間と画面外でタイマーとアニメーションが止まる。
- [ ] 土台（React など）を使うなら、速く変わる状態を画面全体の状態に置いていない。使うかどうかではなく、`measure.mjs` の値で判断する。

## 指摘の出し方

1件ごとに、場所・何が問題か・直し方を書く。重いものから並べる。

```
[重い] ログの流れ（#c-log）: error の行を赤だけで示している。色覚の違いで見分けられない。
       → 行頭に [ERROR] を付ける。
[中]   トースト: 削除のたびに確認ダイアログが出る。取り消せる操作なので確認は慣れて読まれなくなる。
       → 確認をやめ、トーストに「取り消し」を出す。
[軽い] アイコン copy: 左右の中心が2マスずれている（icon.py の注意）。
       → 右の空きを1マス詰めて描き直す。
```

- 測った数値は、測ったものと目標を分けて書く（「実測 9.5 MB」「目標 16ms、未計測」）。
- 確かめられなかったこと（headless では押せないキー操作など）は、確かめていないと書く。
